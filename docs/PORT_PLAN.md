# План переноса функционала `love_tg_native` в `anbernics/tgmuos_love`

## Цель
Перенести рабочий TDLib-клиент (PC/LÖVE 11.5, feature-based архитектура) в целевой проект для Anbernic/muOS, сохранив архитектуру потоков и UX, адаптировав ввод/разрешение/шрифты.

## Источник и приёмник
- Источник: `/var/home/kyle/Projects/love_tg_native` (PC-клиент, реальный TDLib, FSD-структура).
- Приёмник: `/var/home/kyle/Projects/anbernics/tgmuos_love` (LÖVE 11.5, 640×480, модульный TDLib-клиент; legacy mock сохранён отдельно).

## Этапы

### 1. Подготовка каркаса — выполнено
- `src/` (entities/features/shared) и `threads/` уже перенесены.
- Корневой `main.lua` переключён с mock UI на `src.app.main`; прежняя точка
  входа сохранена в `legacy_main.lua`.
- Корневой `conf.lua` сохраняет identity `tgmuos_love`, 640×480 и fullscreen.

### 2. TDLib и потоки — подключено, требуется проверка на устройстве
- Модульный клиент использует `src/shared/api/tdlib_client.lua` и
  `threads/tdlib_worker.lua`; корневой `telegram.lua` больше не запускается.
- TDLib JSON и медиа-декодер работают в отдельных потоках.
- Сохранить правила: только строки/таблицы через `love.thread.getChannel`; QR-auth через `requestQrCodeAuthentication` → `authorizationStateWaitOtherDeviceConfirmation.link` → QR → обновление токена → `authorizationStateReady`.
- Каталог настроек: `/root/.config/tgmuos_love/telegram.conf`; проверить
  сохранение и восстановление сессии на реальной muOS.

### 3. Экраны — перенесены, требуется функциональная проверка
- Auth: перенести `auth_screen.lua`, `profile_screen.lua`, `settings_screen.lua`, QR-рендер из `src/shared/lib/qr.lua` (валидный, не pseudo).
- Chats: `chat_screen.lua` + helpers/input/media; список чатов, unread, last message.
- Chat: `message_bubble.lua`, history_api (from_message_id=last_message.id), отправка текста/медиа, пагинация.
- Settings: прокси/параметры, хранение `telegram.conf` (права 600 на PC; на устройстве `/root/.config/tgmuos/`).

### 4. Медиа и аватары — перенесены, требуется проверка ресурсов устройства
- Перенести `shared/api/media_*` (avatars, conversion, playback, methods), `chat_screen_media.lua`.
- Адаптировать пути/кэш под `love.filesystem` и разрешение 640×480.

### 5. Ввод и UI — базовая навигация подключена
- D-pad, A/B, START, SELECT, X/Y, L1/R1 и L2/R2 отображаются на действия
  приложения; MENU+A завершает работу.
- Виртуальная клавиатура и полный ввод текста геймпадом ещё не реализованы.
- Проверить раскладку и навигацию в 640×480.

### 6. QR
- Использовать проверенный энкодер (C `qr.c` из tgmuos или Lua-библиотеку), не `qr_lua.lua`/`qr_c.lua` из старых каркасов.
- Добавить тест матрицы QR (размер/валидность).

### 7. Проверка и сборка — хостовый smoke пройден, устройство ожидает
- Все Lua-файлы проходят компиляцию LuaJIT; LÖVE 11.5 запускает проект.
- muOS-пакет собирается через `./build_muOS.sh`; фактическая авторизация
  требует устройства и секретов вне пакета.
- QR-auth, TDLib ARM64, ввод, 60 FPS и память ещё проверить на RG35XX SP.

## Риски
- ARM vs x86_64 `libtdjson.so`; на устройстве нужна сборка под aarch64.
- GCC 16 ICE на `MessagesManager.cpp` → `-O1`.
- Mock QR в старых модулях — не копировать.
- `getChatHistory` семантика (from_message_id=last_message.id).

## Критерии приёмки
- Реальный TDLib вместо mock.
- QR-авторизация работает end-to-end.
- Список чатов и диалог с историей.
- UI 60 FPS, без блокировок главного потока.
- Сессия сохраняется/восстанавливается.

## Текущее состояние и следующий порядок

Каркас `src/` и TDLib-потоки уже присутствуют в приёмнике, но до этого
запускался корневой `main.lua` с mock-клиентом. После переключения точки
входа на `src.app.main` рабочий путь использует TDLib, QR-авторизацию,
списки чатов и существующие feature-модули. Учётные данные ожидаются в
`~/.config/tgmuos_love/telegram.conf` либо через `TG_CONFIG`/`TG_API_ID`/
`TG_API_HASH`. Для управления геймпадом добавлено соответствие d-pad,
A/B, START и SELECT; сочетание GUIDE+A завершает приложение.

| Область | Уже есть в модульном клиенте | Осталось проверить/адаптировать на устройстве |
| --- | --- | --- |
| Авторизация и TDLib | QR, worker-поток, сохранённая БД, proxy | реальная QR-сессия, загрузка ARM-библиотеки и конфиг |
| Чаты и история | список, архив, сообщения, пагинация и поиск | навигация только геймпадом, длинные списки на 640×480 |
| Профиль и настройки | отдельные экраны и запросы TDLib | полный ввод текста без физической клавиатуры |
| Медиа | фото, документы, аудио, видео, WebM/TGS-декодер | доступность FFmpeg/Lottie и расход памяти на RG35XX SP |
| Дополнительные действия | реакции, редактирование, пересылка, поиск | проверка каждого действия с живым аккаунтом |

### Приоритеты портирования

1. **Базовый запуск (в работе):** единая модульная точка входа, TDLib,
   секреты вне пакета, управление геймпадом, сборка и QR-проверка.
2. **Функциональный паритет:** проверить на устройстве список/архив чатов,
   историю, отправку/редактирование, реакции, профили и настройки; затем
   закрывать найденные пробелы по одному.
3. **Медиа:** проверить форматы на реальных сообщениях. WebM-стикеры
   декодируются FFmpeg в фоне; TGS требует `lottie_convert.py`. Устройство
   не должно блокировать UI, если декодер отсутствует.
4. **Производительность и релиз:** ограничить одновременно активные кадры,
   проверить память/FPS на длинной истории и собрать muOS-пакет с ARM64
   `libtdjson.so`; не включать пользовательские конфиги/сессии.

Проверять исходники Lua синтаксисом LuaJIT, а запуск — приложенным runtime
PortMaster LÖVE 11.5. Хостовый AppImage не может загрузить ARM64 TDLib,
поэтому только сборка архива не является подтверждением работы Telegram.
